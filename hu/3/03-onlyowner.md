Ez azért van, mert így működik a szerződés öröklés. Emlékezz:

```
ZombieFeeding is ZombieFactory
ZombieFactory is Ownable
```

Tehát a `ZombieFeeding` is `Ownable`, és hozzáférhet az `Ownable` szerződés függvényeihez / eseményeihez / módosítóihoz. Ez vonatkozik minden olyan szerződésre is, amely a jövőben örökli a `ZombieFeeding`-et.

## Függvény módosítók

Egy függvény módosító pont úgy néz ki, mint egy függvény, de a `modifier` kulcsszót használja a `function` helyett. És nem hívható meg közvetlenül, mint egy függvény — ehelyett a módosító nevét a függvény definíció végéhez csatolhatjuk, hogy megváltoztassuk a függvény viselkedését.

Nézzük meg közelebbről az `onlyOwner`-t:

```
pragma solidity >=0.5.0 <0.6.0;

/**
 * @title Ownable
 * @dev The Ownable contract has an owner address, and provides basic authorization control
 * functions, this simplifies the implementation of "user permissions".
 */
contract Ownable {
  address private _owner;

  event OwnershipTransferred(
    address indexed previousOwner,
    address indexed newOwner
  );

  /**
   * @dev The Ownable constructor sets the original `owner` of the contract to the sender
   * account.
   */
  constructor() internal {
    _owner = msg.sender;
    emit OwnershipTransferred(address(0), _owner);
  }

  /**
   * @return the address of the owner.
   */
  function owner() public view returns(address) {
    return _owner;
  }

  /**
   * @dev Throws if called by any account other than the owner.
   */
  modifier onlyOwner() {
    require(isOwner());
    _;
  }

  /**
   * @return true if `msg.sender` is the owner of the contract.
   */
  function isOwner() public view returns(bool) {
    return msg.sender == _owner;
  }

  /**
   * @dev Allows the current owner to relinquish control of the contract.
   * @notice Renouncing to ownership will leave the contract without an owner.
   * It will not be possible to call the functions with the `onlyOwner`
   * modifier anymore.
   */
  function renounceOwnership() public onlyOwner {
    emit OwnershipTransferred(_owner, address(0));
    _owner = address(0);
  }

  /**
   * @dev Allows the current owner to transfer control of the contract to a newOwner.
   * @param newOwner The address to transfer ownership to.
   */
  function transferOwnership(address newOwner) public onlyOwner {
    _transferOwnership(newOwner);
  }

  /**
   * @dev Transfers control of the contract to a newOwner.
   * @param newOwner The address to transfer ownership to.
   */
  function _transferOwnership(address newOwner) internal {
    require(newOwner != address(0));
    emit OwnershipTransferred(_owner, newOwner);
    _owner = newOwner;
  }
}
```

Figyeld meg az `onlyOwner` módosítót a `renounceOwnership` függvényen. Amikor meghívod a `renounceOwnership`-et, az `onlyOwner`-en belüli kód hajtódik végre **először**. Aztán amikor eléri az `_;` állítást az `onlyOwner`-ben, visszatér és végrehajtja a `renounceOwnership`-en belüli kódot.

Tehát bár vannak más módok a módosítók használatára, az egyik leggyakoribb használati eset egy gyors `require` ellenőrzés hozzáadása egy függvény végrehajtása előtt.

Az `onlyOwner` esetében ennek a módosítónak a hozzáadása egy függvényhez azt teszi, hogy **csak** a szerződés **tulajdonosa** (te, ha te telepítetted) hívhatja meg azt a függvényt.

>Megjegyzés: A tulajdonosnak ilyen speciális hatalmat adni a szerződés felett gyakran szükséges, de rosszindulatúan is használható. Például a tulajdonos hozzáadhat egy hátsó ajtós függvényt, amely lehetővé tenné, hogy bárki zombiját átruházza magára!

>Tehát fontos megjegyezni, hogy csak azért, mert egy DApp az Ethereumon van, nem jelenti automatikusan, hogy decentralizált — valójában el kell olvasnod a teljes forráskódot, hogy megbizonyosodj, nincs benne speciális kontroll a tulajdonos által, ami miatt potenciálisan aggódnod kellene. Van egy gondos egyensúly fejlesztőként egy DApp feletti kontroll fenntartása között, hogy javíthasd a potenciális hibákat, és egy tulajdonos nélküli platform építése között, amelyben a felhasználóid bízhatnak, hogy biztonságban tartják az adataikat.
